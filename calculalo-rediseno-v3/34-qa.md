# Prompt 34 — QA del rediseño v3

Cierre: tests, e2e, build, accesibilidad AA, mismos resultados en las calculadoras, y caza de restos del diseño viejo (planilla) o de cosas que Martín sacó (aviso de independencia, Valores vigentes en la home, etiquetas internas, AdSense).

## Contexto

- Después de 29–33 el sitio tiene que verse como `referencia/capturas/` y respetar `referencia/design-system.md`.
- Scripts del proyecto (`package.json`):
  - `npm test` → `node --import tsx --test tests/*.test.ts` (hoy `tests/calc.test.ts`, lógica de `lib/calc`)
  - `npm run build`
  - `npm run test:e2e` → `tests/e2e/calculadoras.mjs` (levanta `next start` en 3100 tras un build, o usa `BASE_URL`)
- Casos actuales del e2e (no los relajes):
  - `/laboral/sueldo-neto/` `#bruto` 2000000 → 1660000
  - `/laboral/aguinaldo/` `#rem` 2000000 → 830000
  - `/laboral/indemnizacion/` `#rem` 2000000 → > 10000000
  - `/impuestos/ganancias/` `#bruto` 4000000 → 792864.71
  - `/impuestos/monotributo/` `#fact` 20000000 → 66020.12
- Si la tanda 2 ya está y hay tests o e2e de esas calculadoras, también tienen que pasar con los mismos resultados. Si no hay e2e nuevos, no hace falta inventar una batería completa; sí abrí al menos una por categoría nueva y confirmá que calcula.
- El test de home agregado en el 31 tiene que seguir verde.

## Archivos a tocar

Solo los que hagan falta para arreglar fallas de este rediseño: CSS, markup, tests o e2e rotos por selectores. **No** “arregles” un test cambiando el valor esperado de un cálculo. **No** toques `lib/calc` ni `data/` salvo un bug de UI que no tenga nada que ver con la fórmula (no debería hacer falta).

## Pasos

1. Corré `npm test`. Tiene que pasar entero, incluida la lógica de las 5 calculadoras originales (y la tanda 2 si hay tests).

2. Corré `npm run build` y después `npm run test:e2e`. Las 5 vivas dan los mismos resultados de siempre. Si el e2e de la home se agregó en el 31, también.

3. Restos del diseño viejo: buscá en el repo (código, CSS, docs de UI, tests) y eliminá o actualizá lo que quedó:

   - Fuentes y tokens: Bricolage, Public Sans, `--font-bricolage`, `--font-public`, `--f-tit`, `--f-txt`, `--papel`, `--verde`, `--ambar`, `--papel-2`, `--verde-claro`. No tiene que quedar el woff2 viejo en `app/fonts/`.
   - Copy de la home vieja: “Hacé la cuenta”, “Con la norma de este mes”, “Más usadas”, lista `.ranking` en la home.
   - Bloque “Valores vigentes” en la home (tope ANSES / ICL / UVA / IPC como aside de portada). Puede seguir existiendo la data y usarse dentro de una calculadora; no en la home.
   - Leyenda de independencia: “sitio independiente”, “no pertenece al Estado”, “aviso-indep”.
   - Etiquetas internas en la UI: “Tanda 2”, badges “Nueva” de equipo.
   - Regla `.nav li:nth-child(n+3){display:none}`.
   - daisyUI / Tailwind, si alguien los dejó colgados y no se usan.
   - Espacios, slots o reservas de altura para AdSense o anuncios (en código, CSS o `docs/design-system.md`). Si aparecen, sacalos: no van.
   - `themeColor` que no sea `#0B4F5B`.
   - Links a fonts.google.com para estas familias.

4. Accesibilidad AA, revisión manual (y automática si ya hay herramienta; no hace falta instalar una suite pesada si no está):

   - `lang="es-AR"`, un H1 por página, skip link, landmarks (`header` / `nav` / `main` / `footer`).
   - Contraste: texto ≥ 4,5:1; componentes de interfaz y `--linea` ≥ 3:1 (hex y ratios en `referencia/design-system.md`). El cobre `#C45C1A` no lleva texto blanco.
   - Foco visible 3px `--marca`. Controles y filas clicables ≥ 44px, en especial el nav en 390px.
   - Labels asociados, `aria-current`, `aria-live` en el resultado, HTML de tablas / `dl` / `fieldset` válido.
   - En 390px se ven todas las categorías con contenido del nav.

5. Recorré visualmente y compará con `referencia/capturas/`:
   - Home desktop 1440 (completa y fold) y mobile 390.
   - Sueldo neto desktop 1440 (completa y fold) y mobile 390.
   - Un hub (p. ej. `/laboral/`).
   - Header y footer en todas: sin independencia, footer con descargo orientativo.

6. Corregí lo que encuentres (CSS, markup, tests de selectores). Volvé a correr `npm test`, `npm run build` y `npm run test:e2e`. Dejá una lista breve de lo que revisaste y de lo que arreglaste, al final del PR o en un comentario: no hace falta un informe largo.

## Criterios de aceptación

- `npm test`, `npm run build` y `npm run test:e2e` pasan.
- Las 5 calculadoras vivas dan los mismos resultados que antes (casos del e2e y de `tests/calc.test.ts`). Las de la tanda 2, si están, también.
- No quedan restos de la planilla (fuentes, tokens, H1 viejo, ranking en la home), ni Valores vigentes en la home, ni leyenda de independencia, ni etiquetas internas, ni slots de AdSense.
- AA: contraste, foco, 44px, un H1, skip link, nav completo en mobile.
- Visual alineado con las capturas aprobadas.
- Dominio, canonical, metadataBase, JSON-LD y URLs intactos.

## Qué no tocar

- Valores esperados de los tests de cálculo (no “actualizar” un número para que el test pase).
- `lib/calc/**`, `data/`, `SITE.url`, `metadataBase`, canonical, JSON-LD, slugs.
- Deploy. No agregues AdSense.

## Cómo verificar

```bash
npm test
npm run build
npm run test:e2e
```

Abrí `/`, `/laboral/`, `/laboral/sueldo-neto/` en 1440 y 390 y compará con `referencia/capturas/`. Buscá en el código los strings del punto 3 y confirmá que no quedan.
